# ADR-0003: Human-approved project intent and portable approval provenance

- **Status:** Accepted

Autonomous planning and issue dispatch require a human-approved project specification revision; a plan may not invent the initial user intent. Approval decisions are durable append-only events bound to the reviewed subject digest, with current status columns retained only as projections. The first plan always requires human approval; later low-risk replans may activate automatically only when they preserve the approved specification and requirement set and exclude deployment or migration work. An explicit human issue created in a project is recorded as manual provenance and does not authorize autonomous dispatch. Bundle approvals preserve their source provenance but never open the receiving project's execution gate; a local adoption approval is required. Existing active projects whose derived specification lacks local approval are blocked from new autonomous issue creation; work already in progress may finish, and the backfill leaves plan and node status untouched. This keeps intent and execution authority local while allowing audit history to travel.

The approval-event trigger rejects ordinary updates and deletes unless the workspace teardown transaction enables its purge flag. The configured application database role is trusted: the managed `multica` role is a PostgreSQL superuser and can set that flag or bypass the trigger. The flag is an accidental-mutation guard, not a privilege boundary against a compromised application database identity; introducing a constrained runtime role is outside this decision.
